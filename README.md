# いちご市場ダッシュボード（食べチョク）

食べチョクの「いちご」検索結果に出てくる商品を**毎日1回**自動で取得し、
価格・内容量・1kgあたり価格・推定販売ペースを蓄積して、ダッシュボードで日別に確認できるようにするツールです。
運用代行先（大分県のいちご農家）の価格設定を決めるための「価格レコメンド」も表示します。

## 画面でわかること

| セクション | 内容 |
|---|---|
| KPI | 販売中の商品数 / 1kgあたり価格の中央値 / 商品価格の中央値 / 推定販売数（7日平均）/ 売り切れ率。それぞれ7日前比つき |
| 1kgあたり価格の推移（折れ線） | 中央値と、中央50%の価格帯の推移 |
| 推定販売数の推移（棒＋折れ線） | 市場全体の1日あたり推定販売数と7日移動平均 |
| 価格レコメンド | 内容量（g）と現在価格を入れると、推奨価格・売れ行き急落ライン・市場相場を表示 |
| 価格帯別の販売ペース | 1kgあたり価格帯ごとの平均販売ペース。推奨帯（オレンジ）と急落ライン以上（グレー）を色分け |
| 価格と販売ペースの分布 | 商品ごとの散布図（クリックで商品詳細） |
| 商品一覧 | 価格・内容量・円/kg・7日前比・販売ペース・レビュー数・在庫状態。並び替え・CSV出力可 |
| 商品詳細 | 行クリックでその商品の価格と販売ペースの推移を表示 |
| 価格改定と販売ペースの変化 | 値上げ・値下げした商品の、変更前後7日の販売ペース比較 |

品種・都道府県・送料込/別・内容量・キーワードで絞り込むと、すべてのグラフとレコメンドに反映されます。

## データの取り方

食べチョクの[「いちご」検索結果](https://www.tabechoku.com/products/categories/200001?keyword=%E3%81%84%E3%81%A1%E3%81%94)（約1,000件・50件/ページ）だけを毎日取得します。
商品カードに載っている「商品名・価格・送料・内容量・レビュー数・評価・産地・生産者・掲載順」を記録し、商品ページは開きません。
サイトのアクセス制限にかからないよう、リクエスト間隔は15秒（`request_interval_sec`）、1日あたり約20リクエストです。

## 「販売数」の推定方法（重要）

食べチョクは商品ごとの販売数を公開していないため、次の方法で**推定**しています。

1. 商品カードに「残りN個」の在庫表示がある場合 → 前日からの在庫減少数
2. ない場合（ほとんどの商品） → レビュー件数の増加 ÷ レビュー投稿率（`config.json` の `review_rate`、初期値 10%）

絶対数ではなく、**商品同士・期間同士の相対比較**として使ってください。
自社（代行先）の実際の販売数とレビュー増加数を比べて `review_rate` を補正すると精度が上がります。

## レコメンドの考え方

1. 内容量が近い（指定gの1/2〜2倍）販売中の商品を比較対象にする
2. 直近14日の「1kgあたり価格」で 500円刻み（`price_band_width`）の価格帯に分ける
3. 価格帯ごとに 1商品あたりの平均販売ペースを出し、
   - **急落ライン**：それより安い帯のピークから販売ペースが40%以上落ちる最初の帯
   - **推奨価格**：急落ラインより下で「価格 × 販売ペース」（＝売上）が最大の帯の中央値
4. 現在価格を入れると、市場内の位置（安い方から何%）と、値下げ/値上げの目安を表示

## 構成

```
config.json             取得URL・レビュー投稿率・自社商品IDなどの設定
scraper/scrape.py       検索結果一覧を取得し data/snapshots/YYYY-MM-DD.csv を保存
scraper/parse.py        内容量（g）・品種・都道府県・価格の抽出
scraper/build.py        スナップショットを集計して docs/data.js を生成
scraper/demo.py         デモデータ生成（動作確認用）
docs/                   ダッシュボード（静的HTML。GitHub Pages で公開可能）
.github/workflows/daily.yml  毎朝 5:47(JST) に取得→集計→コミット
```

日次スナップショットは CSV なので、Excel でそのまま開いて分析にも使えます。

## セットアップ

1. このブランチを `main` にマージ（GitHub Actions の定期実行はデフォルトブランチでのみ動きます）
2. GitHub の **Settings → Actions → General → Workflow permissions** を「Read and write」に
3. **Actions → daily-scrape → Run workflow** で初回を手動実行
   - 成功すると `data/snapshots/` に当日のCSVが追加され、ダッシュボードが実データに切り替わります
   - `debug-html` アーティファクトに取得したHTMLのサンプルが保存されます。項目が取れていない場合はこれを見てパーサを調整します
4. **Settings → Pages** で `main` ブランチの `/docs` を公開すると、ブラウザからダッシュボードを見られます
   （公開範囲に注意。社外秘にしたい場合はリポジトリを private にし、Pages の公開設定を確認してください）
5. 代行先の商品IDを `config.json` の `own_product_ids` に入れると、表と散布図で強調表示されます

ローカルで動かす場合:

```bash
pip install -r requirements.txt
python -m scraper.scrape            # 実データ取得
python -m scraper.build             # docs/data.js を生成
# デモデータで画面を見る場合
python -m scraper.demo && python -m scraper.build --snapshots data/demo_snapshots --demo
python -m http.server -d docs 8000  # http://localhost:8000
python -m unittest discover -s tests -t .
```

## 注意事項

- 取得前に食べチョクの利用規約・robots.txt を確認してください。アクセス間隔は `request_interval_sec`（初期値2秒）で調整できます。
- サイトのHTML構造が変わると取得項目が欠けることがあります。Actions のログに「価格取得 N / 内容量取得 N」が出るので、急に減ったらパーサの見直しが必要です。
- 1回の取得は約20リクエスト・5〜6分です。アクセス制限（HTTP 405等）を受けた場合はそこまでのデータを保存して終了します。
