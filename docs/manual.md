# 運用マニュアル・計算ロジック

> このページの内容は `docs/manual.md` から自動生成しています。`{{ }}` で囲まれた数値は設定ファイル（`config.json`）と自動実行の設定から毎日読み込むため、設定を変えると自動で書き換わります。

## 1. このダッシュボードの目的

大分県のいちご農家さんの「食べチョク」運用代行で、**価格設定の根拠を出す**ためのツールです。

- 食べチョクで売られているいちごの価格・内容量・1kgあたり価格を毎日記録する
- 他の商品がどれくらい売れているかを推定し、「この価格を超えると売れ行きが落ちる」という線を見つける
- 代行先の商品に「いくらに設定するとよいか」をレコメンドする

## 3. 取得するデータ

**対象**：[食べチョクの「いちご」検索結果]({{search_url}})のうち、おすすめ順の上位 {{max_pages}} ページ（約{{max_products}}件）。

**1商品ごとに記録する項目**

| 項目 | 内容 |
|---|---|
| 商品名・生産者・産地 | 産地は都道府県と市町村 |
| 品種 | 商品名から判定（あまおう、とちおとめ、ベリーツなど） |
| 種類 | 生果 / 冷凍 / 加工品（ジャム・ドライ・ケーキなど）。商品名から判定 |
| 価格・送料 | 価格は税込。送料は一覧に表示される金額 |
| 内容量（g） | 一覧の内容量欄、なければ商品名から読み取り |
| 1kgあたり価格 | 価格 ÷ 内容量 × 1000 |
| レビュー件数・評価 | 販売数の推定に使います |
| 在庫の状態 | 販売中 / 予約受付 / 売り切れ / 残り◯個 |

**除外ルール**：商品名に「いちご／イチゴ／苺／🍓」、いちごの品種名、「◯◯ベリー」（ブルーベリー等を除く）のいずれも含まれない商品は「いちご以外」として保存しません。

## 4. 計算ロジック

### 内容量の読み取り

1. 「1kg」「約500g」「270g×4パック」のような表記から総重量を計算します
2. 「4パック」のようにパック数だけの場合は、1パック {{default_pack_grams}}g として推計します（表に「推計」と表示）
3. 「15粒」のように粒数だけの場合は、1粒 {{default_berry_grams}}g として推計します（同上）
4. 1kgあたり価格が {{ppk_min}}円〜{{ppk_max}}円 の範囲外になる商品は、読み取りミスとみなして価格の集計から外します

### 推定販売数

食べチョクは販売数を公開していないため、前日との差分から推定します。

1. 在庫数（残り◯個）が前日より減っていれば、**減った数**を販売数とする
2. それ以外は **レビュー件数の増加 ÷ レビュー投稿率（{{review_rate_pct}}%）** を販売数とする（購入者の {{review_rate_pct}}% がレビューを書くと仮定）
3. 取得できなかった日があれば、間の日数で割って1日あたりにならす

「販売/日（7日・14日・30日）」は、それぞれ直近の期間の1日あたり平均です。

### 指標カード・推移グラフ

| 指標 | 計算方法 |
|---|---|
| 販売中の商品数 | 売り切れでない商品の数（予約受付を含む） |
| 1kgあたり価格（中央値） | 販売中の商品の1kgあたり価格の中央値。グラフの帯は25〜75パーセンタイル |
| 商品価格（中央値） | 販売中の商品の価格の中央値 |
| 推定販売数/日 | 全商品の推定販売数の合計。カードは直近7日平均 |
| 売り切れ率 | 売り切れの商品数 ÷ 掲載商品数 |

いずれも画面上部の絞り込み（種類・品種・産地・送料・内容量）を反映します。

### 価格レコメンド

1. **比較対象を選ぶ**：販売中の商品のうち、入力した内容量の 1/{{weight_ratio}}〜{{weight_ratio}}倍 の商品（12件未満なら絞り込み条件に合う全商品）
2. **価格帯に分ける**：直近14日の平均の1kgあたり価格で、{{price_band_width}}円刻みの価格帯に分ける
3. **価格帯ごとの販売ペース**：各帯の商品の「販売/日（14日）」の平均を出す
4. **急落ライン**：安い帯から順に見て、それまでのピークから販売ペースが **{{cliff_drop_pct}}%以上** 落ちる最初の帯の下限
5. **推奨価格**：急落ラインより安い帯のうち「帯の中央価格 × 販売ペース」（＝売上の目安）が最大の帯の中央価格。入力した内容量に換算し、10円単位で丸めます
6. 商品数が少ない帯（比較対象が30件以上なら3件未満、それ以外は2件未満）は判定に使いません
7. 現在価格を入れると、比較対象の中での位置（安い方から何%か）と、値上げ・値下げの目安を表示します

販売データが2日分そろうまでは「データ蓄積中」と表示します。

### 価格改定と販売ペースの変化

前日と価格が変わった商品について、変更前7日間と変更後7日間の「推定販売数/日」の平均を比べます。

## 5. 画面から読み取ること

1. **相場の把握**：1kgあたり価格の中央値と帯から、代行先の価格が高い方か安い方かを確認する
2. **需要の波**：推定販売数の7日平均が上がり始めたら、需要が立ち上がったサイン。出品数や予約開始の時期の判断に使う
3. **売り切れ率**：上昇しているときは供給不足で、値上げしても売れやすい
4. **価格レコメンド**：代行先の内容量と価格を入れ、推奨価格・急落ラインと比べる。「急落ラインを超えているので◯円以下に」という提案の根拠にする
5. **価格改定の実例**：他の農家さんの値下げ・値上げで売れ行きがどう変わったかを、農家さんへの説明材料にする
6. **売れ筋の構成**：商品一覧を掲載順や販売/日で並べ、売れている商品の内容量・価格・送料の組み合わせを参考にする
7. **地元・同品種の比較**：都道府県＝大分県、品種＝ベリーツで絞り込んで競合を確認する

## 6. 注意点・限界

- **推定販売数は目安です**。絶対数ではなく、商品同士・期間同士の相対比較に使ってください。代行先の実際の販売数とレビュー増加数を比べると、レビュー投稿率（現在 {{review_rate_pct}}%）を実態に合わせられます
- **レビューは届いた後に付く**ため、販売数の推定は実際の注文より遅れて表れます。特に10〜11月の予約注文は、出荷が始まる12〜1月まで数字に表れません
- **本格的に使えるのは12月〜5月の旬の時期**です。レコメンドは2〜3週間分のデータがたまってから目安になります
- 対象はおすすめ順の上位約{{max_products}}件です。代行先の商品が圏外になる場合は、個別に追う仕組みの追加が必要です
- 「送料込」の商品は1kgあたり価格が高めに出ます。比べるときは「送料」で絞り込んでください
- このページとデータは公開リポジトリにあるため、誰でも見られます
